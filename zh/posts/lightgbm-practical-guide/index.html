LightGBM 很容易跑出第一个结果，却不容易用对。实际项目中，问题通常不在 fit() 本身，而在四个相互关联的选择：训练接口是否用对，目标函数是否匹配任务，验证集是否模拟线上数据，以及树的容量与正则化是否协调。

本文默认读者已经理解决策树、梯度提升、过拟合和交叉验证，不再从信息增益等基础概念讲起。重点是如何把 LightGBM 用于二分类、多分类、回归和 Learning-to-Rank，怎样理解常用参数的真实作用，以及如何根据训练现象定位问题。

版本说明

文中的 API 与参数以 LightGBM 4.7 稳定文档为准。4.7 的 sklearn 包装器新增 eval_X、eval_y，并弃用 eval_set=[(X_valid, y_valid)]；若项目仍使用 4.6 或更早版本，请把示例中的 eval_X、eval_y 改为 eval_set。正式项目应固定依赖版本，不要让同一份训练代码随环境自动升级。

LightGBM 的实现特点如何影响使用

LightGBM 仍然是加法形式的梯度提升模型。第 ttt 轮在已有预测 Ft−1F_{t-1}Ft−1​ 上加入一棵新树 ftf_tft​，学习率 η\etaη 控制本轮更新幅度：

Ft(x)=Ft−1(x)+ηft(x)F_t(x)=F_{t-1}(x)+\eta f_t(x)Ft​(x)=Ft−1​(x)+ηft​(x)

与其他 GBDT 实现相比，LightGBM 的几个工程选择会直接反映在参数上。

直方图分裂：连续特征先离散到有限个 bin，节点寻找切分点时遍历 bin，而不是遍历所有原始取值。max_bin 控制离散粒度，min_data_in_bin 控制单个 bin 的最小样本量，subsample_for_bin 控制构造 bin 时抽取多少样本。减小 max_bin 通常降低时间和内存开销，但也可能丢失细粒度切分。

leaf-wise 生长：每次只分裂当前收益最大的叶子，而不是按层扩展整棵树。在相同叶子数下，这通常能更快降低训练损失，也容易形成很深的小样本分支。因此，num_leaves、min_child_samples 和 min_child_weight 往往比单独设置 max_depth 更关键。

原生类别分裂与稀疏优化：类别特征可以按类别集合切分，不必先展开成 one-hot；稀疏输入也有专门的直方图优化。类别编码、缺失值和稀疏矩阵中的零因此都有明确语义，不能只把数据转成数值后不加检查地交给模型。

LightGBM 原始论文重点提出 GOSS 和 EFB；当前版本将 GOSS 作为 data_sample_strategy="goss"，而 boosting_type 用于选择 gbdt、dart 或 rf。这与旧版本把 goss 写在 boosting_type 中不同。算法概览可参考官方特性说明和原始论文。

构造器、fit() 与预测接口分别控制什么

sklearn 包装器的构造器负责定义模型：objective 决定训练损失；boosting_type 和树参数决定怎样建树；learning_rate 与 n_estimators 决定提升过程；采样和正则参数约束方差；random_state、n_jobs、device_type 决定随机性和计算后端。

fit() 接收当前数据集才有的内容：X、y、sample_weight、categorical_feature、验证数据、验证指标和 callbacks。排序任务还需要 group 与 eval_group，init_model 则用于从已有模型继续训练。

预测阶段常用参数如下：

  • num_iteration：使用多少轮；若存在 best_iteration_ 且未显式指定，默认会使用最佳轮数；
  • raw_score=True：返回变换前的 margin，而不是概率或最终预测；
  • pred_leaf=True：返回每棵树落入的叶节点索引；
  • pred_contrib=True：返回逐特征贡献，最后一列是期望值；
  • validate_features=True：输入是 pandas DataFrame 时，检查预测列是否与训练列匹配。

objective 和 eval_metric 不能互相替代。前者产生训练梯度和 Hessian，后者只负责衡量验证表现。模型可以用二元 log loss 训练、用 AUC 早停，但这不等于训练过程中直接优化 AUC。

分类任务：LGBMClassifier

二分类的目标、指标与输出

二分类使用 objective="binary"，标签必须是 0/1。predict_proba(X)[:, 1] 返回正类概率，predict(X) 返回类别标签；业务阈值应从概率出发单独选择，不要把默认类别结果当成成本最优决策。

正类稀少且关注头部average_precision 或外部 PR AUCPrecision@K、Recall@K 与容量 K

下面的基线使用 AUC 早停，同时在训练结束后独立计算 log loss。

import lightgbm as lgb
from sklearn.metrics import log_loss, roc_auc_score

categorical_columns = ["country", "device_type", "channel"]
for column in categorical_columns:
    X_train[column] = X_train[column].astype("category")
    X_valid[column] = X_valid[column].astype(X_train[column].dtype)

classifier = lgb.LGBMClassifier(
    objective="binary",
    n_estimators=5_000,
    learning_rate=0.03,
    num_leaves=31,
    min_child_samples=100,
    subsample=0.8,
    subsample_freq=1,
    colsample_bytree=0.8,
    reg_lambda=1.0,
    random_state=42,
    n_jobs=-1,
    verbosity=-1,
)

classifier.fit(
    X_train,
    y_train,
    eval_X=X_valid,
    eval_y=y_valid,
    eval_metric="auc",
    categorical_feature=categorical_columns,
    callbacks=[
        lgb.early_stopping(
            stopping_rounds=200,
            first_metric_only=True,
            min_delta=1e-5,
            verbose=False,
        ),
        lgb.log_evaluation(period=100),
    ],
)

valid_probability = classifier.predict_proba(
    X_valid,
    num_iteration=classifier.best_iteration_,
)[:, 1]

print("best iteration:", classifier.best_iteration_)
print("AUC:", roc_auc_score(y_valid, valid_probability))
print("log loss:", log_loss(y_valid, valid_probability))

n_estimators=5_000 是轮数上限，不是模型一定会训练 5,000 轮。早停会把最佳轮数写入 best_iteration_；n_iter_ 或 n_estimators_ 记录实际完成的轮数。min_delta 用于过滤小到没有实际意义的指标波动。

如果 boosting_type="dart"，early_stopping() 回调不会生效，这是官方回调接口的明确限制。使用 DART 时必须另行确定轮数，不能照搬上述训练方式。

类别不平衡时，三个“权重”不是一回事

scale_pos_weight 只调整二分类中的正类权重，一个常见起点是 N−/N+N_{-}/N_{+}N−​/N+​。is_unbalance=True 让 LightGBM 根据类别分布处理不平衡，两者不能同时使用。sample_weight 是逐样本权重，可以表达曝光量、抽样概率修正或不同样本的业务成本。

这些权重会改变训练损失，不等同于修改分类阈值。官方文档也提醒，类别权重可能使单样本概率估计变差。若概率本身有业务含义，需要在未参与模型拟合的校准集上重新做 Platt scaling 或 isotonic calibration。

pos_bagging_fraction 和 neg_bagging_fraction 可以分别抽取正负样本，但必须同时设置并启用 bagging_freq。启用 balanced bagging 后，普通 bagging_fraction 会被忽略。它改变的是每轮用于建树的样本，不是损失权重。

多分类需要关注每轮树的数量

多分类通常使用 objective="multiclass"，对应 softmax；multiclassova 则使用 One-vs-All。sklearn 包装器会根据标签推断类别数，原生接口需要设置 num_class。常用指标是 multi_logloss、multi_error，也可以在外部计算 macro/micro F1、每类召回率和混淆矩阵。

multiclassifier = lgb.LGBMClassifier(
    objective="multiclass",
    n_estimators=3_000,
    learning_rate=0.04,
    num_leaves=63,
    min_child_samples=80,
    class_weight="balanced",
    random_state=42,
    n_jobs=-1,
)

multiclassifier.fit(
    X_train,
    y_train,
    eval_X=X_valid,
    eval_y=y_valid,
    eval_metric="multi_logloss",
    callbacks=[lgb.early_stopping(150, first_metric_only=True)],
)

class_probability = multiclassifier.predict_proba(X_valid)
predicted_class = multiclassifier.classes_[class_probability.argmax(axis=1)]

若有 KKK 个类别，LightGBM 每个 boosting iteration 内部会构造 KKK 棵树。因此，“500 轮四分类”实际包含约 2,000 棵树，训练时间、模型大小和推理延迟都会随类别数增长。多分类调优时，应同时记录 iteration 数和总树数。

回归任务：LGBMRegressor

回归并不只有均方误差。目标函数决定模型把哪种误差看得更重，也决定预测值的统计含义。

数据与决策目标objective关键参数典型指标
对大误差惩罚更重、预测条件均值regression无专用参数rmse、l2
对异常值较稳健、预测条件中位数regression_l1无专用参数l1
保留二次损失的平滑性，同时降低异常值影响huberalphahuber、MAE、RMSE
预测 P10/P50/P90 等条件分位数quantilealpha 为目标分位点quantile、pinball loss
非负计数或发生次数poissonpoisson_max_delta_stepPoisson deviance
正值、右偏的连续响应gamma无通用形状参数gamma、gamma_deviance
含大量零且正值右偏的总损失类响应tweedietweedie_variance_powertweedie

目标函数要依据标签生成过程和业务损失选择，而不是哪个离线分数看起来更高。比如，regression 对单个大残差非常敏感；如果标签中有真实但极端的大值，这种敏感性可能正是业务需要，不能仅以“抗异常值”为由改成 L1。

均值回归或稳健回归

下面使用 Huber 目标训练，并同时记录 MAE 与 RMSE。alpha 控制 Huber 目标的参数，不能与分位数任务中的 alpha 脱离目标函数单独解释。

import lightgbm as lgb
from sklearn.metrics import mean_absolute_error, mean_squared_error

regressor = lgb.LGBMRegressor(
    objective="huber",
    alpha=0.9,
    n_estimators=5_000,
    learning_rate=0.03,
    num_leaves=31,
    min_child_samples=100,
    reg_lambda=1.0,
    random_state=42,
    n_jobs=-1,
)

regressor.fit(
    X_train,
    y_train,
    eval_X=X_valid,
    eval_y=y_valid,
    eval_metric="l1",
    callbacks=[
        lgb.early_stopping(200, first_metric_only=True),
        lgb.log_evaluation(100),
    ],
)

valid_prediction = regressor.predict(X_valid)
print("MAE:", mean_absolute_error(y_valid, valid_prediction))
print("RMSE:", mean_squared_error(y_valid, valid_prediction) ** 0.5)

这里明确让 l1 控制早停，RMSE 在训练结束后独立计算。若业务按平方误差结算，则应把早停指标改成 rmse。一个训练实验最好只有一个明确的早停主指标，其他指标作为诊断信息记录。

分位数回归用于预测区间

LightGBM 的 quantile 每次只拟合一个分位点。要得到 P10、P50、P90，需要分别训练三个模型：

quantile_models = {}
quantile_predictions = {}

for alpha in (0.1, 0.5, 0.9):
    model = lgb.LGBMRegressor(
        objective="quantile",
        alpha=alpha,
        n_estimators=4_000,
        learning_rate=0.03,
        num_leaves=31,
        min_child_samples=100,
        random_state=42,
    )
    model.fit(
        X_train,
        y_train,
        eval_X=X_valid,
        eval_y=y_valid,
        eval_metric="quantile",
        callbacks=[lgb.early_stopping(200)],
    )
    quantile_models[alpha] = model
    quantile_predictions[alpha] = model.predict(X_valid)

分别训练不能保证任意样本都满足 q^0.1≤q^0.5≤q^0.9\hat q_{0.1}\leq\hat q_{0.5}\leq\hat q_{0.9}q^​0.1​≤q^​0.5​≤q^​0.9​，因此上线前必须检查 quantile crossing。预测区间也不自动等于具有严格覆盖率保证的置信区间；需要在独立数据上检查实际覆盖率，并在需要时使用 conformal calibration 等外部方法校准。

Poisson、Gamma 与 Tweedie 的选择边界

这三个目标都不是“让预测非负”的普通开关，而是对响应分布和均值—方差关系作出不同假设。Poisson 适合计数率一类问题；Gamma 适合严格为正、右偏的连续量；Tweedie 常用于零质量与正连续量并存的总损失。tweedie_variance_power 的范围是 [1,2)[1,2)[1,2)，接近 1 时更靠近 Poisson，接近 2 时更靠近 Gamma。

在使用这些目标前，应检查标签取值域、零值比例、曝光量是否需要作为权重或 offset，以及业务真正评估的是总量、频率还是单次严重度。只因为普通回归产生少量负预测就改目标，往往会掩盖问题定义不清。

排序任务：LGBMRanker

Learning-to-Rank 的观测单位不是彼此独立的行，而是 query 内的候选集合。搜索中一个 query 对应一次检索及其文档候选；推荐中可以对应一次请求及其候选商品。模型输出是用于 query 内排序的分数，跨 query 比较分数通常没有意义。

标签和 group 的约束

lambdarank 与 rank_xendcg 都要求整数相关性标签，数值越大表示越相关。对于 lambdarank，默认 label_gain 将等级映射为 0,1,3,7,15,…0,1,3,7,15,\ldots0,1,3,7,15,…；如果业务等级的效用不符合该映射，应显式设置 label_gain。

group 不是逐行的 query ID，而是按当前行顺序给出的各 query 样本数。例如，三个 query 分别有 4、2、5 个候选，则 group=[4, 2, 5]，并且 sum(group)=11。数据必须先按 query 排在连续区间内。验证集同样需要自己的 eval_group。

切分必须以 query 为单位。同一 query 的候选不能一部分进入训练集、一部分进入验证集，否则 group 结构被破坏，验证也会泄漏同一次请求的信息。

一个完整的 LambdaRank 训练模板

import lightgbm as lgb

train_frame = train_frame.sort_values("query_id", kind="stable")
valid_frame = valid_frame.sort_values("query_id", kind="stable")

feature_columns = [
    column
    for column in train_frame.columns
    if column not in {"query_id", "relevance"}
]

X_train = train_frame[feature_columns]
y_train = train_frame["relevance"].astype("int32")
train_group = (
    train_frame.groupby("query_id", sort=False)
    .size()
    .to_numpy()
)

X_valid = valid_frame[feature_columns]
y_valid = valid_frame["relevance"].astype("int32")
valid_group = (
    valid_frame.groupby("query_id", sort=False)
    .size()
    .to_numpy()
)

ranker = lgb.LGBMRanker(
    objective="lambdarank",
    n_estimators=4_000,
    learning_rate=0.03,
    num_leaves=63,
    min_child_samples=50,
    lambdarank_truncation_level=13,
    label_gain=[0, 1, 3, 7],
    random_state=42,
    n_jobs=-1,
)

ranker.fit(
    X_train,
    y_train,
    group=train_group,
    eval_X=X_valid,
    eval_y=y_valid,
    eval_group=[valid_group],
    eval_metric="ndcg",
    eval_at=[5, 10],
    callbacks=[lgb.early_stopping(200, first_metric_only=True)],
)

valid_score = ranker.predict(X_valid)
valid_result = valid_frame[["query_id", "relevance"]].copy()
valid_result["score"] = valid_score
valid_result["rank"] = (
    valid_result.groupby("query_id")["score"]
    .rank(method="first", ascending=False)
)

示例主要优化 NDCG@5 和 NDCG@10。lambdarank_truncation_level 控制训练重点考虑多少个顶部结果，官方建议它通常略高于目标 NDCG@k，因此目标是 @10 时可从 13 一类的值开始比较，而不是无条件照抄。

rank_xendcg 是另一种排序目标。官方参数文档将其描述为速度更快、性能与 lambdarank 相近的选择，但这不是对所有数据集的保证；应在相同 query 切分和相同 eval_at 下实测。排序评估还应按 query 分析：平均 NDCG 可能掩盖短列表、长列表或不同流量来源之间的明显差异。

原生 Dataset、train() 与 cv()

sklearn 包装器适合大多数表格项目；需要复用二进制 Dataset、自定义目标函数、原生 CV 或精确控制参数时，可以使用原生 API。

import lightgbm as lgb

train_data = lgb.Dataset(
    X_train,
    label=y_train,
    categorical_feature=categorical_columns,
)
valid_data = lgb.Dataset(
    X_valid,
    label=y_valid,
    categorical_feature=categorical_columns,
    reference=train_data,
)

params = {
    "objective": "binary",
    "metric": ["auc", "binary_logloss"],
    "learning_rate": 0.03,
    "num_leaves": 31,
    "min_data_in_leaf": 100,
    "feature_fraction": 0.8,
    "bagging_fraction": 0.8,
    "bagging_freq": 1,
    "lambda_l2": 1.0,
    "verbosity": -1,
}

booster = lgb.train(
    params=params,
    train_set=train_data,
    num_boost_round=5_000,
    valid_sets=[valid_data],
    valid_names=["valid"],
    callbacks=[
        lgb.early_stopping(200, first_metric_only=True),
        lgb.log_evaluation(100),
    ],
)

valid_probability = booster.predict(
    X_valid,
    num_iteration=booster.best_iteration,
)

验证 Dataset 使用 reference=train_data，可共享训练集构造的 bin mapper。默认情况下，Dataset 构造完成后可以释放原始输入；只有之后确实还要访问原始数据或修改 Dataset 时，才需要设置 free_raw_data=False。

lgb.cv() 接收 Dataset，并可通过 folds 传入 sklearn splitter 或显式索引。它返回每轮的验证均值和标准差；设置 return_cvbooster=True 还能拿到各折 Booster。时间序列、实体分组和排序任务不应依赖默认随机折，必须传入符合数据生成过程的 folds。

自定义目标函数需要返回每个样本的 gradient 与 Hessian；自定义指标返回 (metric_name, metric_value, maximize)。使用自定义目标后，传入指标函数的预测值通常是未经概率变换的 raw margin。实现前应对梯度、Hessian、数组形状和数值稳定性分别做单元测试。

数据输入：类别、缺失和样本权重

类别特征

pandas 无序 category 列可以由包装器自动识别，也可以显式传给 categorical_feature。底层会将类别值转换为 int32；类别编码最好从 0 开始连续排列，负值会被当作缺失，浮点类别会向 0 截断。训练、验证和线上推理必须共享同一个 CategoricalDtype，否则相同整数可能表示不同类别。

低到中等基数类别可以先比较原生类别分裂与 one-hot。高基数 ID 列则要单独审查：用户 ID、商品 ID 很容易使模型记忆训练样本，随机切分下的高分可能在新用户或未来商品上消失。cat_smooth 与 min_data_per_group 可以抑制小类别过拟合，但不能修复泄漏或错误切分。

缺失值与稀疏矩阵中的零

LightGBM 默认原生处理缺失值，通常无需为“模型能够训练”而做均值填充。是否添加缺失指示列取决于缺失本身有没有业务信息。

默认 zero_as_missing=False：NaN 是缺失，稀疏矩阵未存储位置按零处理。设置 zero_as_missing=True 后，显式零和稀疏矩阵未存储位置都会当作缺失。如果零表示“次数为 0”或“金额为 0”，开启该参数会改变特征含义。详细规则见官方进阶主题。

sample_weight、曝光量和抽样修正

样本权重必须非负。它可以表示不同观测的可靠性、抽样概率倒数或业务成本，但会直接改变目标函数中各样本的贡献。训练集使用 sample_weight 时，验证集若也需要同一种加权口径，应同步传 eval_sample_weight，外部指标也必须使用相同权重，否则早停指标与最终报告并不一致。

排序任务中的 sample_weight 仍是逐行权重，group 是 query 边界，两者不能互相替代。回归中的曝光量究竟应作为权重、特征还是 offset，取决于标签是总量、频率还是单位暴露率，不能仅靠接口名称决定。

参数详解：哪些参数控制同一件事

树容量：num_leaves、max_depth、叶子下限

num_leaves 是 leaf-wise 树的主要容量上限。增大它允许一棵树表达更多局部交互，也增加过拟合、模型体积和推理成本。若显式设置 max_depth=d，应保证 num_leaves <= 2^d；但 leaf-wise 树通常不平衡，实践中的合理叶子数常明显小于这个理论上限。

min_child_samples 限制叶子样本数，底层根据 Hessian 近似实现，因此偶尔可能看到实际样本数略低于设定值。min_child_weight 则直接限制叶子 Hessian 和。在分类概率接近 0 或 1、样本权重差异大时，Hessian 和与原始样本数可能相差很大，两项约束应分别检查。

对二阶目标，未考虑 L1 时，叶子输出可近似写为：

wleaf≈−∑igi∑ihi+λ2w_{\text{leaf}}\approx- \frac{\sum_i g_i}{\sum_i h_i+\lambda_2}wleaf​≈−∑i​hi​+λ2​∑i​gi​​

gig_igi​ 和 hih_ihi​ 分别是当前预测处的一阶、二阶导数，λ2\lambda_2λ2​ 对应 reg_lambda。min_child_weight 决定证据是否足以形成叶子，reg_lambda 决定已形成的叶子输出收缩多少；两者作用位置不同。

min_split_gain 要求分裂至少带来指定增益。提高它可以同时减少很弱的分裂和训练时间，但固定数值依赖目标函数与样本权重尺度，不适合跨任务照搬。

提升过程：学习率、轮数与 boosting 类型

learning_rate 与 n_estimators 必须一起调。较小学习率只在允许更多轮数时才有意义。常见做法是把树数设为较大的上限，通过同一验证方案早停，再比较不同学习率下的分数、最佳轮数、模型大小和训练时间。

boosting_type="gbdt" 是可靠的默认起点。dart 会随机丢弃已有树以增加正则，但早停回调无效，且还要调 drop_rate、skip_drop 等参数。rf 是随机森林模式，需要满足 bagging 与特征采样条件。不要把 boosting 类型和普通超参数放进一个巨大搜索空间；先用 GBDT 建立可信基线，再单独比较替代模式。

当前版本的 GOSS 由 data_sample_strategy="goss" 选择。它保留大梯度样本，并抽取一部分小梯度样本来估计分裂收益。GOSS 不是普通均匀行采样，不能仅凭相同采样比例与 bagging 对比。

行采样与列采样

subsample < 1 只有在 subsample_freq > 0 时才生效。subsample_freq=1 表示每轮重新抽样，值为 5 表示每 5 轮重新抽样一次。只设置 subsample=0.8 而保留默认 subsample_freq=0，不会得到预期的 bagging。

colsample_bytree 每棵树抽取一次特征；原生 feature_fraction_bynode 则每个节点抽取特征。后者能增加随机性，但官方文档指出它不能像按树采样那样加速；两者同时小于 1 时，有效候选比例是二者乘积。

extra_trees=True 会让每个特征在一个节点只检查一个随机阈值，可以提速并增加随机性。它改变切分搜索方式，适合单独做消融，而不是默认与激进的行列采样同时开启。

正则化：L1、L2、平滑和叶输出上限

reg_alpha 对叶输出施加 L1 正则，更容易把弱叶输出压到 0；reg_lambda 施加 L2 正则，连续地收缩大输出。两者通常按对数尺度搜索，例如从 10−310^{-3}10−3 到 10210^2102，同时保留 0 作为无正则基线。

path_smooth 将子节点输出向父节点平滑，对小叶子尤其有用；设置为正值时，min_data_in_leaf 至少要为 2。max_delta_step 限制单棵树叶输出，最终限制量是 learning_rate * max_delta_step。当少量叶子产生极端 margin 时，它比盲目提高全局 L2 更有针对性。

直方图：max_bin、min_data_in_bin、subsample_for_bin

max_bin 越大，候选切分越细，Dataset 占用和分裂计算通常越高。默认 255 并非精度必需值；大数据或 GPU 训练可比较 63、127、255。降低后要重新评估连续变量中窄阈值是否仍能被识别。

min_data_in_bin 防止非常少的样本形成独立 bin。subsample_for_bin 只控制构造 bin 边界时抽多少行，不是每棵树的 bagging；稀疏或分布长尾数据中，过小的取样量可能让 bin 边界失真。

原生 Dataset 创建后，部分与 bin 构造相关的状态不会随普通训练参数重新计算。若调 min_data_in_leaf 并复用同一个 Dataset，要注意默认 feature_pre_filter=True 可能已依据第一次构造时的参数过滤特征。稳妥做法是为相关 trial 重建 Dataset，或在理解内存与速度代价后关闭预过滤。

类别与单调约束参数

cat_smooth 和 min_data_per_group 用于抑制小类别或高基数类别的过拟合。max_cat_threshold、max_cat_to_onehot 等参数影响类别分裂候选与何时采用 one-vs-other 方式，只有在类别特征确实成为瓶颈时才值得进入搜索空间。

monotone_constraints 按特征顺序接收 1、-1、0，分别表示单调增加、单调减少和不约束。它适用于有明确业务先验的数值特征，不能用于类别特征。错误的约束会直接压低模型上限；输入列顺序变化则可能把约束施加到错误特征，因此约束向量必须属于特征契约的一部分。

验证设计必须匹配数据生成过程

线上要泛化到什么合理验证方式典型泄漏
同分布的新样本分层随机切分或分层 K 折极不平衡却不分层
新用户、新设备、新商品GroupKFold 或实体留出同一实体跨训练与验证
未来时间窗口滚动或扩展窗口切分随机切分把未来信息给过去
新 query 的候选排序query 级切分同一 query 被拆到两个集合

目标编码、频次统计、聚合特征、缺失统计、特征筛选和概率校准都必须在每个训练折内部拟合，再应用到对应验证折。先对全量数据做完这些步骤再 K 折，只是把泄漏包装成了交叉验证。

早停也属于模型选择。调参、选特征、定阈值和早停都应使用训练数据内部的验证折；最终测试集尽量只做一次无偏评估。时间任务还要给特征留出真实的数据延迟，例如预测次日流失时，不能使用次日结束后才完整生成的统计特征。

一套可执行的调参顺序

先确定基线和搜索预算

先固定数据版本、切分索引、目标函数、首要指标、随机种子、线程数和单 trial 时间预算。记录每折指标、标准差、最佳轮数、训练时长、模型大小和关键分群结果。没有这些基线，搜索器返回的第四位小数没有判断价值。

容量参数可以从下面的范围开始，但必须随样本量调整：

capacity_space = {
    "num_leaves": [15, 31, 63, 127],
    "max_depth": [-1, 6, 8, 10, 12],
    "min_child_samples": [20, 50, 100, 300, 1_000],
    "min_child_weight": [1e-3, 1e-2, 1e-1, 1.0, 10.0],
}

若训练分数好、验证分数差，先减小 num_leaves，提高两个叶子下限；若训练和验证都差，再检查特征与目标函数，然后才是增大容量。max_depth 更适合做明确的延迟或规则复杂度限制，不应单独承担全部正则化。

再调随机化与正则

在少数合理容量附近搜索：

regularization_space = {
    "subsample": [0.6, 0.8, 1.0],
    "subsample_freq": [1],
    "colsample_bytree": [0.6, 0.8, 1.0],
    "reg_alpha": [0.0, 1e-3, 1e-2, 1e-1, 1.0, 10.0],
    "reg_lambda": [0.0, 1e-3, 1e-2, 1e-1, 1.0, 10.0],
    "min_split_gain": [0.0, 1e-3, 1e-2, 1e-1],
}

正则参数跨多个数量级，应做对数采样。特征很少时，不要把 colsample_bytree 降得过低；正类极少时，激进行采样会进一步减少每轮正样本。任何收益都要看跨折稳定性，而不是只看最佳 trial。

最后联合学习率与轮数

固定较好的结构后，比较 0.1、0.05、0.02、0.01 等学习率，每档给足轮数上限，并使用相同早停规则。最优轮数总撞上限，说明上限不足；几十轮就停止且训练、验证都差，可能是容量不足或学习率过大。学习率降低时，早停耐心通常也要增加。

完成 K 折后，可以用最佳轮数的中位数作为全量重训候选值。若还有时间更靠后的独立验证窗口，则继续早停更稳妥。不能根据最终测试集反向选择轮数。

如果外层并行多个 trial，每个模型的 n_jobs 应受限，避免“trial 并行数 × 模型线程数”超过物理核心数。调参目标也不应只有离线分数；延迟、内存和模型大小是硬约束时，应先剔除超预算 trial，再在可行模型中选择稳定解。

根据训练现象定位问题

现象先验证什么参数层面的下一步
训练好、验证差泄漏、实体/时间切分、特征漂移减叶子、增叶子下限、加采样或正则
训练和验证都差标签质量、目标函数、缺失特征增容量或改特征，不要先堆正则

速度、内存与可复现性

CPU 上，n_jobs=-1 不保证最快。小数据的线程协调开销可能超过收益；官方建议以物理核心数为起点实测。减少树数、叶子数、候选特征或 bin 数都能降低计算量，但它们改变模型容量，必须与精度一起评估。

GPU 更适合规模大、较稠密的数据。官方 GPU 调优指南建议从较小的 max_bin（例如 63）开始比较，并指出单精度通常更快。小数据可能被数据传输和启动开销抵消。CPU、OpenCL GPU 与 CUDA 后端之间的功能、速度和数值结果可能不同，迁移后要重新评估，而不是只测一次训练时间。

需要限制内存时，可以降低 max_bin 和 num_leaves，保持稀疏输入，并用 histogram_pool_size 限制历史直方图缓存。force_col_wise=True 往往更节省 Dataset 内存；force_row_wise=True 在样本多、总 bin 较少或使用较小 bagging 时可能更快，但会使 Dataset 内存占用翻倍。两者不能同时设置，应以基准测试决定。

固定 random_state 仍不足以跨平台逐位复现。还要记录 LightGBM 版本、编译器、硬件、线程数、数据顺序和所有 seed。CPU 上若要求同一环境下更稳定，可以设置 deterministic=True，并显式选择 force_col_wise=True 或 force_row_wise=True；代价可能是训练变慢。不同版本、编译方式或系统之间不应预期完全一致。

解释模型时避免把重要性当结论

importance_type="split" 统计特征参与分裂的次数，"gain" 累计这些分裂的训练增益。可切分点多的连续特征、高基数类别，以及彼此相关的特征，都可能使这两类重要性产生偏差。

较稳妥的分析组合是：用 gain/split 做快速检查；在独立验证集上计算 permutation importance；对单样本用 pred_contrib=True 或 SHAP 查看贡献；再用特征消融确认关键变量是否真的改善验证结果。所有这些结果都描述模型如何使用特征，不自动构成因果结论。

解释首先应该服务于排错。若时间戳后的字段、人工审核结果或目标的直接代理变量排在最前，应先检查泄漏；若模型高度依赖缺失模式，要确认线上缺失机制是否稳定；若某个类别 ID 主导预测，要在新实体切分上重新验证。

保存模型时一并保存特征契约

模型文件之外，还需要保存：

  • 特征名、顺序、dtype、类别词表、未知类别和缺失值约定；
  • 预处理代码或可版本化的特征流水线；
  • 标签定义、训练时间范围、切分索引和样本权重口径；
  • 完整参数、最佳轮数、依赖版本、代码提交标识；
  • 分类阈值、概率校准器以及它们使用的数据范围；
  • 总体与分群指标、模型大小和端到端推理延迟。
classifier.booster_.save_model(
    "lightgbm-model.txt",
    num_iteration=classifier.best_iteration_,
)

服务上线前，使用固定样本对训练端与服务端预测做逐条对拍，并启用 validate_features=True 检查 DataFrame 列。线上至少监控输入分布、缺失率、未知类别率、预测分布、延迟，以及延后才能获得的真实业务指标。模型漂移时，先定位标签口径、特征可用性或校准变化，再决定是否重训。
